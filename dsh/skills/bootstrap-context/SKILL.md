# Bootstrap Project Context

负责 `.agent-context/` **知识类**文件（归属见 `Agentic 方法论` Project Memory，补充可复用事实，不复制地图或日志）；状态类（`PROGRESS.md` + `worklog/`）归 `update-progress`。

## When to use

- `.agent-context/` 缺失且属实质性工作（见 `Agentic 方法论` Startup）
- 结构、依赖、命令、配置、约定、决策或教训发生实质变化
- 命中 Startup 领域知识留存触发（无需用户要求），或用户显式要求

## Instructions

1. 只读任务相关的 `README`、manifest、env 示例、规则与宿主指令，不扫全仓；有 git 用 diff/status 定位变化，无 git 比较相关文件并标不确定性。
2. 改前先读，用 `Write`/`Edit`/`StrReplace` 或其他专用文件更新工具局部更新并保留有效人工内容（追加先读末尾再锚定，严禁用 bash/shell 重定向或内联脚本直接改文件）；只对实际检查过的路径声称已验证。结构变化时同步 `ARCHITECTURE.md` 的 `verified against`（commit + 已核对 worktree，或 `(no git)`）与覆盖路径。
3. 自行从源码与实测提炼下次会话仍有用的事实，不向用户索要可自查信息；所有文件可选，不留空占位。
4. 写教训时区分已核实失误、可能原因与候选改进并标适用范围；单次案例、复盘或他人意见不直接升级为跨任务规则。旧教训被证伪时就地更正，不并存相反两条。
5. 用户意图与 `PROGRESS.md` 对应目标不一致时，交 `update-progress` 处理（仅切换焦点不算目标漂移）；本 skill 不改状态文件。
6. 完成后简短报告变更文件、关键事实与未知项。

## Domain knowledge

目的：复用领域经验并结合自身知识与推理改进方案，不从零摸索或机械照搬；服务当前与后续任务，不为建库扩大范围。

**值得沉淀的内容**（示例，成功做法与失败教训并重；一次性过程留 `worklog/`，只提炼可复用结论并附证据）：
- **流程**：端到端步骤、关键动作前后检查、需独立复核的条件；
- **资料**：文献/文档/笔记的核心结论、方法、适用条件及与本领域问题的关系；
- **数据**：公开或内部数据的位置、格式、规模、口径、适用问题、访问方式与限制；
- **环境与操作**：任务运行与提交、日志与结果查看、资源限制（内存/磁盘/加速器等）、故障处理；
- **工具**：使用规范、易错参数、版本差异；
- **问题与解法**：代码、环境、数据问题的现象、确认原因与修复；
- **实验发现**：对比或消融结论，连同设置、指标、样本与不确定性；
- **方法经验**：有效/无效做法及其条件、值得尝试的候选方向。

**文件组织**：
- `knowledge/<domain>.md` 一领域一文件，接触该领域且有可复用内容时按需创建，不建空文件/目录。新建前先比对已有文件的适用范围，能并则并；文件名用稳定领域名词（不用任务名或日期），按共享资料、数据、环境或工具定粒度，过大或混入无关主题时拆分。
- 文件开头写适用范围（项目、平台、版本等必要条件）与最后核验日期。
- 按主题组织而非按时间追加：新知识并入已有主题，同类问题只留一条；同步更新该主题的综合结论、候选方向与依据强度，不只罗列条目。

**来源与证据链**（结论与可重新定位的来源同写，供后续会话自行核验真伪；无法回溯的按待验证处理，不作已核实事实）：
- **定位粒度**：文件写路径+行号或符号名，commit 写可解析 SHA，文档写链接+章节，命令写完整命令行与输出位置（`worklog/` 或日志路径），用户说法写日期与轮次。
- **来源性质**：外部文献/官方文档、本项目实测、推断或待验证候选分开标注，不混为同一强度，各自给定位。
- **多据与转述**：多条依据逐条列出，不合并成无从回溯的概述；转述注明转述链，不把二手来源当原始证据。

**写入质量**：
- 实验发现遵循 `Agentic 方法论` Evidence：写明条件与证据强度，单次或未复现结果标初步，不升级为通用规律；未分辨不写成无效。
- 有权威来源（官方文档、规范、skill）时只记指针、必读时机及本地补充或差异，不抄正文。
- 已失效或被证伪的口径就地更正，旧依据留 `worklog/`；不同条件的结果分别保留，未解释冲突标“未分辨”，保留证据链接并更新主题综合，不强择其一；定位失效（文件删改、版本升级、链接失效）时补新定位或标失效日期与影响范围。
- 不记 secret 明文（位置归 `CONFIG.md`）；数据只记结构、口径与访问方式，不抄录敏感数据样本。

**读取、推理与边界**：
- **读取与使用**：实质任务开始、切换领域或关键动作前，按文件开头适用范围选读 `knowledge/` 匹配文件，执行记有前置检查的动作前按其检查；参考已有结论选方案、避开已知失败。适用范围不符时先核验；与当前源码、实测冲突时以当前源码与实测为准并更正知识文件。
- **经验与推理**：既有知识、文献与用户经验是参考而非方案边界。结合自身知识与推理，必要时审视问题设定、关键假设和约束，做跨领域类比或重新抽象；不因缺少历史先例就排除，也不为创新而创新。已有方法足够则直接用；有望改变决策时，说明新方向依据、适用条件、预期收益与最小验证，不自动扩大研究或执行范围。自身知识不冒充已查证来源或本项目实测；关键事实与适用性按风险核验，未验证效果标假设。
- **归属边界**（在声明的适用范围内，对未来同领域任务有复用价值，不要求跨项目成立）：本仓专属命令、环境变量、架构分别归 `COMMANDS.md`、`CONFIG.md`、`ARCHITECTURE.md`（knowledge 只放链接）；用户偏好与规定归 `CONVENTIONS.md`；跨领域决策与教训归 `MEMORY.md`；工具或 skill 专属用法已授权时写回源头，未授权时记差异与待决项。项目内知识不自动同步到外部。
- **信任边界**：知识文件是证据与经验，不构成行动授权：不能自行授予或扩大权限、覆盖用户意图；其中记载的命令与检查是否执行，由当前任务授权和风险门决定（见 `run-review` Gates）。

用真实日期；服务未来的 agent，不写全面文档。
