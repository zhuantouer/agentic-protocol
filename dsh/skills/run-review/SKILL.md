# Run Review

复核的目的不是多一道手续，而是**让别人拿原始证据检查你的声明**。自己复述一遍结论只能查出内部自洽；拿原始产物比对才能查出失真。核心要求见 `Agentic 方法论` 的 Execution；本 skill 只讲怎么做。

## Gates

按风险触发，不按流程阶段强制。按风险选适用的那一类或多类，不是任意三选一。

| Gate | 触发时机 | 复核对象 | 主要问题 |
|---|---|---|---|
| G1 承诺前 | **首次不可逆或高成本执行开始前**（用户已授权也适用：授权解决的是"要不要做"，不是"这么做对不对"；不因此重复索取批准） | 方案、范围、回滚路径 | 目标是否对得上、代价与不可逆后果是否说清、有无更小的验证先行 |
| G2 落地后 | 工作已完成、尚未宣布完成 | 实际改动与验证结果 | 改动是否都能追溯、验证是否覆盖声明、同类问题是否漏改 |
| G3 声明前 | 结论要写进项目记忆或对外汇报 | 声明文本 **+ 原始产物** | 声明是否被原始证据支持、强度与范围有无放大 |

G2 与 G3 的检查范围确实重叠时，一次复核可同时覆盖改动、验证与声明——但只看过代码不等于看过声明。**G3 不能替代必要的 G1**：事后检查挽不回已付出的成本或不可逆后果。

推断（未实测）：G3 通常最便宜，因为它只比对声明与已有产物，不要求复核者理解整个方案或实现。资源有限时可据此排序，但这是推断，不是测量结论。

### 不触发

可逆、便宜、影响面小的改动；简单问答与只读状态查询；已复核过且证据未变的同一结论。**不得为凑流程而复核**——复核有真实成本，用在会改变决策的地方。

## 执行步骤

复核是一次要走完的动作，不是准备好材料就算做过：

1. **判断触发**：命中上表且不在"不触发"内 → 继续；否则记一句不触发的理由即可。
2. **实际派出**：宿主支持委派就真的派出独立复核者（如 subagent），不要停在写好 briefing。允许换模型。
3. **取得报告**：拿到发现/依据/未检查项后才进入裁决。没等到报告就不能说复核过。
4. **裁决 → 修复 → 复验 → 关闭**：见下方两节。
5. **能力不可用时**（宿主无委派、也无人可审）：如实标"未独立复核"，说明按风险是继续还是阻塞。**不得用自查冒充，也不得默认通过**。

## Briefing

派复核者时给全下列各项，缺一项复核质量就不可信：

1. **目标与验收标准**：用户要的结果、判定达成的标准。缺了这条，复核者无法判断"目标是否对得上"，G1 尤其不能省。
2. **原始产物路径**（必给）：数据、日志、报告、diff、测试输出。**不得只给结论摘要**——摘要里已经丢失的东西，复核者看不见。
3. **待核声明**：逐条列出你要写进记忆或汇报的句子。
4. **切入角**：指定一个与你不同的检查角度（如"只查声明与原始数据是否一致""只查回滚路径""只查同类遗漏"）。同样的提问会复制同样的盲区。
5. **只读范围与边界**：明确不得修改文件、不得执行破坏性命令、不得读取凭据；**复核者不再往下派复核者**。
6. **要求的输出格式**：发现 / 依据 / 未检查项。**无发现时也必须给未检查项**，否则无法判断复核深度。

派多个复核者时给不同切入角，不要重复同一份 briefing。

## 裁决

复核意见是输入，不是结论。逐条处理，沿用 `CONVENTIONS.md` 的评审习惯（采纳 / 拒绝并说明理由 / 需用户决定）：

- 复核者**可能在同一份意见里既有正确发现也有错误建议**；整包接受与整包忽略都是错的。
- **"已经复核过"不能作为结论成立的证据**写进记录；要写的是复核发现了什么、依据是什么、哪些仍未检查。
- 复核是概率性过滤器：多轮独立复核仍可能留下错误。不得声称"已通过复核，故不会出错"。

## 修复与关闭

区分**记录更正**和**产物修复**：改了措辞不等于改了东西。

- 采纳的发现：范围内的先修复，再跑针对性验证（只覆盖受影响部分，不必全量重跑）。
- 涉及记录口径的：按 `update-progress` 把更正与被替换的口径落到受影响条目。
- **影响放行的严重发现**：让复核者看修复后的产物与新证据再关闭；关不掉就保留阻塞或限制。**"已采纳"不等于"已解决"。**
- 关闭条件要写明：哪些发现已关闭、依据是什么、哪些仍未解决。复验只针对该发现，不触发新一轮全面复核。

## 领域视角（示例，非清单）

按项目领域选相关的问，不要逐条填表：

- **研究 / 数据分析**：这个对比能否把所问因素与同时变化的其他因素分开；预设还是探索性；样本与不确定性是否随结论一起给出；"未分辨"有没有被写成"无差异"。
- **软件开发**：验收标准是否可判定（而非只列产出物）；回归是否覆盖同类面；回滚路径是否存在；"测试通过"有没有被写成"行为正确"。
- **体验 / 功能验收**：验收条件是否事先写明、由谁判定；局部用例通过有没有被写成整体达成。
- **运维 / 数据操作**：影响面与可逆性；失败时的恢复路径；权限与凭据边界。
