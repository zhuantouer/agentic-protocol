# Run Review

让独立复核者拿原始产物核对你的方案、改动与声明（自查只能发现内部矛盾，查不出相对原始证据的失真）。核心要求见 `Agentic 方法论` Execution。

## Gates

按 Execution 风险判据触发，按风险选适用的一类或多类，不是任意三选一，也不按阶段强制。有效后续核对只用于安排复核时机或避免重复复核：须确认其在生效前执行、针对实际生效产物覆盖相关风险，且发现问题能阻止生效；未覆盖的风险仍按需复核。不能假定用户会检查，也不能以自查替代独立复核。

| Gate | 触发时机 | 复核对象 | 主要问题 |
|---|---|---|---|
| G1 承诺前 | **首次不可逆、成本高或影响面大的执行开始前，或使这些后果可以发生的动作前**（用户已授权也适用：授权定"做不做"，复核查"做法对不对"，不重复求批） | 方案、范围、回滚路径 | 目标是否对齐、代价与不可逆后果是否说清、有无更小验证先行 |
| G2 落地后 | 工作已完成、尚未宣布完成 | 实际改动与验证结果 | 改动是否均可追溯、验证是否覆盖声明、同类问题是否漏改 |
| G3 声明前 | 结论写入项目记忆或对外汇报前 | 声明文本 **+ 原始产物** | 声明是否受原始证据支持、强度与范围有无放大 |

G2 与 G3 范围重叠时可合并一次复核（但只看代码不等于看过声明）。**G3 不能替代必要的 G1**（事后检查挽不回已发生代价或不可逆后果）。推断（未实测）：G3 只比对声明与现成产物，通常最便宜，资源受限时可优先，但属推断非实测。

### 不触发

可逆、便宜、影响面小的改动；简单问答与只读状态查询；已复核且证据未变的同一结论。**不为凑流程复核**，只用于会改变决策处。

## 执行步骤

1. **判断触发**：命中上表且不在"不触发"内则继续；否则记一句不触发理由。
2. **实际派出**：宿主支持委派时实际派出独立复核者（如 subagent，可换模型），不停留在写 briefing。
3. **取得报告**：拿到发现、依据与未检查项后才进入裁决。
4. **裁决 → 修复 → 复验 → 关闭**：见下两节。
5. **能力不可用时**：如实标"未独立复核"，按风险说明继续或阻塞；**不得用自查冒充，也不默认通过**。

## Briefing

派复核者时须给齐以下各项：
1. **目标与验收标准**：用户要的结果与判定标准（G1 尤不可省）。
2. **原始产物路径**（必给）：数据、日志、报告、diff、测试输出；**不得只给结论摘要**。
3. **待核声明**：逐条列出拟写入记忆或汇报的原句。
4. **切入角**：指定与你不同的检查角度（如只查声明与原始数据一致性、回滚路径或同类遗漏），避免复制盲区；派多人时各给不同切入角。
5. **只读边界**：不得改文件、执行破坏性命令或读凭据；**复核者不再往下派复核者**。
6. **输出格式**：发现 / 依据 / 未检查项（**无发现也须列未检查项**，以判复核深度）。

## 裁决

复核意见是输入而非结论，沿用 `CONVENTIONS.md` 的评审习惯逐条裁决（采纳 / 拒绝并说明理由 / 需用户决定）：
- 同一份意见可兼有正确发现与错误建议，不整包接受或忽略。
- **"已经复核过"不能作为结论成立的证据**；记录须写明发现了什么、依据为何、哪些仍未检查。
- 复核是概率性过滤，不得声称"已通过复核故不会出错"。

## 修复与关闭

区分**记录更正**与**产物修复**（改措辞不等于改产物）：
- **采纳项**：范围内先修复，再跑受影响部分的针对性验证；涉及记录口径的按 `update-progress` 落到受影响条目。
- **影响放行的严重发现**：复核者核对修复后产物与新证据才可关闭；未解决则保留阻塞或限制（**"已采纳"不等于"已解决"**）。
- **关闭记录**：写明已关闭发现、依据及未决项；复验仅针对该发现，不重跑全面复核。

## 领域视角（按需选问，非必填清单）

- **研究 / 数据分析**：对比能否分离所问因素与混杂变化；预设还是探索性；样本与不确定性是否齐备；"未分辨"是否被写成"无差异"。
- **软件开发**：验收标准是否可判定；回归是否覆盖同类面；有无回滚路径；"测试通过"是否被写成"行为正确"。
- **体验 / 功能验收**：验收条件是否事先写明、由谁判定；局部通过是否被写成整体达成。
- **运维 / 数据操作**：影响面与可逆性；失败恢复路径；权限与凭据边界。
