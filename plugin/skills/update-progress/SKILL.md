# Update Progress

遵循 `Agentic 方法论` 的写入触发：当前状态与历史证据分开存——地图只记现在，过程与证据进 `worklog/`，两者不重复。

## Instructions

1. 先读相关内容，保留仍有效的人工记录；识别本次工作所属目标，推断内容标 assumption。
2. 区分焦点切换、新增目标和目标变化：切换只更新焦点/任务引用；新增并行目标或子目标进 `Other Goals`，保留所属关系与各自验收标准；目标或标准实质变化只替换对应条目的失效口径。主目标确实被替换时，未结案旧线移到 `Other Goals`。旁支提问不改目标，不建目标树。
3. 仅已回答（含有证据的否定）或用户明确放弃的条目移到 `Closed Questions`；切换、暂停或某个方法失败不等于结案。有效验收标准保留，失效口径另标适用范围。
4. 独立判断两类写入：满足下方证据判据就写 worklog，即使结论不变；仅目标、焦点/任务状态、结论/缺口、next check、milestone 或相关链接变化时更新 `PROGRESS.md`。两者均无才不写。先保存证据及被替换口径的变更理由，再于同一轮更新受影响条目；决定性验证、限制与阻塞留在地图，细节用链接。
5. 结论被撤回或降级时，同一轮定向检查依赖它的条目：当前结论、`Next Check`、`Deferred`、已排队动作与知识类文件；保留历史更正与证据链接，不留仍以有效口径指导行动的旧结论。
6. 写完复核实际文本：数值与其单位、方向、样本量是否一致，链接锚点是否存在，标题与摘要是否比来源证据更强。
7. 简短报告结论与缺口；仅在有用时给下一步。不建 handoff、不按天建空日志、不自动执行积压项。

## Write criteria

仅当本次工作至少产生以下一项时才写 worklog：

- 尝试过外部写操作：不论成功、失败、无变化或结果未知，本回合记录目标对象、请求值（含适用单位）、结果与验证依据；未验证就标未知，不记录 secret。相同任务可合为一节，但保留各操作结果；
- 改变当前结论或后续决策的证据；
- 可复用的验证结果；
- 失败但排除了一个合理方案；
- 需要跨会话保留的重要决策及理由；
- 明确的阻塞、限制或未验证风险。

过程性工具调用、不满足上述任一证据判据的重复检查、只读状态查询不记录。

数值或比较类结论要连同判定依据一起写：观察对象、样本或范围、不确定性、以及它是预设检查还是结果到手后才想到的。缺哪项就写明缺失，不用"约""基本"替代。

## Progress template

标题保持英文，这样跨项目的链接与恢复都稳定；正文用项目语言。`Current State` 是当前格式的标志。省略用不到的章节，但不要省略不确定性。

```markdown
# Project Progress

## Objective
[主目标与当前有效口径；不追加历史，不因处理某个子目标而覆盖主目标。]
**目标**：[一句话，沿用用户措辞。]
**当前验收标准**：[可判定标准与证据；推断的标 assumption，未知则写明，不省略；未分辨不记为零。]
**当前子目标**：[可选：当前聚焦目标/子目标的名称或链接及下一决策点；已在 Other Goals 记录的只引用。]

## Other Goals
[可选：其他开放目标或并行子目标。每条写名称、目标、所属目标（引用 Objective 或其他条目，无父项标独立）、验收标准、状态（并行推进 / 暂停 / 等待前置）、下一决策点或恢复条件、证据链接；不因切换焦点移除。]

## Closed Questions
[可选：问题/目标、所属目标（或独立）、有效验收标准或稳定引用、状态（已回答 / 明确放弃）、结论或放弃理由、适用条件、证据或决定链接。仅有失效口径时注明其范围；结案不自动废弃验收标准。]

## Constraints
[可选：范围、非目标、投入上限和用户约束。]

## Current State
[按所属目标关联当前任务、日期/版本、结论、验证缺口、阻塞及相关链接；不重复目标定义，无任务可写 "No active task"。]

## Next Check
[可选：所属目标 → 缺口 → 动作与预期证据 → 决策或停止条件。]

## Milestones
- [可选：粗粒度结果、日期、证据链接；合并旧项。]

## Deferred
- [可选：机会与再次查看条件；不代表已批准。]
```

## Daily log template

只在有值得留存的工作时建日志，日期用用户本地工作日期，不是下次会话。连续的工作留在原文件里直到产生新结果。追加前先读当天已有内容，绝不覆盖其他任务。

```markdown
# Work Log — YYYY-MM-DD

## Pilot
[目的/任务；仅在需要时给前序条目链接。]
- Work and evidence: [结果、决定性命令/来源/产物、验证、局限。]
- Conclusion: [预期 vs 实际；对目标的影响，包含被证伪的假设。]
```

小标题要能说明内容且保持稳定，同一天内唯一；保留被链接的锚点。从 PROGRESS 引用：`worklog/YYYY-MM-DD.md#task`；日志之间：`YYYY-MM-DD.md#task`。链接前先确认文件/标题存在。不要把整张状态图或每次工具调用都抄进日志。

## Recovery and growth

1. 完整读 `PROGRESS.md`；信息不足时跟随当前任务链接。
2. 没有链接时按任务搜索日志并只读匹配章节；不按日期批量加载、不建空日志、不复制旧笔记。
3. 保持地图可完整重读：细节进日志，合并旧 milestone，移除过时链接但保留结论、决定性限制和相关证据。不建日志索引或第二层归档。
4. 可复用的命令、偏好、领域知识和跨领域教训分别归 `COMMANDS.md`、`CONVENTIONS.md`、`knowledge/<domain>.md`、`MEMORY.md`，只链接不复制；不列 touched files。

## Legacy migration

`HANDOFF.md` 之类的旧快照是只读的迁移来源：可以读、可以把内容并进 `worklog/` 和 `PROGRESS.md`，但不得往里写新内容，也不得新建一个。仅当遇到尚不含 `Current State` 章节的旧格式 progress 或 `HANDOFF.md` 时，读 `references/legacy-migration.md`。
