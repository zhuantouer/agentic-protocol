# Update Progress

遵循 `Agentic 方法论` 写入触发：地图（`PROGRESS.md`）只记当前状态，过程与证据入 `worklog/`，互不重复。

## Instructions

1. 先读相关内容，保留有效人工记录；确认工作所属目标，推断项标 assumption。
2. 区分焦点切换、新增目标与目标变化：切换只改焦点/任务引用；新增并行目标或子目标入 `Other Goals`（保留所属关系与验收标准）；目标或标准实质变化只替换对应条目的失效口径；主目标被替换时未结案旧线移入 `Other Goals`。旁支提问不改目标，不建目标树。
3. 仅已回答（含证据否定）或用户明确放弃的条目移入 `Closed Questions`；切换、暂停或单次方法失败不等于结案。保留有效验收标准，失效口径注明适用范围。
4. 独立判断两类写入：满足下方判据即写 worklog（即使结论未变）；仅目标、焦点/任务状态、结论/缺口、next check、milestone 或相关链接变化时更新 `PROGRESS.md`；均无则不写。先写证据与口径变更理由，再同轮更新地图；决定性验证、限制与阻塞留地图，细节用链接。
5. 结论撤回或降级时，同轮检查依赖它的当前结论、`Next Check`、`Deferred`、已排队动作与知识文件；保留更正与证据链接，清除仍作有效指导的旧口径。
6. 写完核对：数值、单位、方向、样本量是否一致，链接锚点是否存在，标题与摘要是否强于来源证据。
7. 简短报告结论与缺口，仅在必要时给下一步。不建 handoff、不按天建空日志、不自动执行积压项。

## Write criteria

仅当产生以下至少一项时写 worklog（过程性工具调用、不满足判据的重复检查、只读查询不记）：
- 尝试过外部写操作：不论成功、失败、无变化或结果未知，本回合记目标对象、请求值（含单位）、结果与验证依据（未验证标未知，不记 secret；同任务可合节但保留各操作结果）；
- 改变当前结论或后续决策的证据；
- 可复用的验证结果；
- 排除合理方案的失败实验；
- 需跨会话保留的重要决策及理由；
- 明确的阻塞、限制或未验证风险。

数值或比较结论须附判定依据：观察对象、样本或范围、不确定性、预设还是事后探索；缺项写明缺失，不用"约""基本"替代。

## Progress template

标题保持英文以稳定跨项目链接与恢复；正文用项目语言。`Current State` 为当前格式标志。省略空章节，但不省略不确定性。

```markdown
# Project Progress

## Objective
[主目标与当前有效口径；不追加历史，不因处理子目标覆盖主目标。]
**目标**：[一句话，沿用用户措辞。]
**当前验收标准**：[可判定标准与证据；推断标 assumption，未知写明，未分辨不记为零。]
**当前子目标**：[可选：当前聚焦目标/子目标名称或链接及下一决策点；已在 Other Goals 的只引用。]

## Other Goals
[可选：并行或子目标。写名称、目标、所属目标（引用父项或标独立）、验收标准、状态（并行推进 / 暂停 / 等待前置）、下一决策点或恢复条件、证据链接；不因切换焦点移除。]

## Closed Questions
[可选：问题/目标、所属目标（或独立）、有效验收标准或引用、状态（已回答 / 明确放弃）、结论或放弃理由、适用条件、证据链接。失效口径注明范围；结案不自动废弃验收标准。]

## Constraints
[可选：范围、非目标、投入上限与用户约束。]

## Current State
[按所属目标记当前任务、日期/版本、结论、验证缺口、阻塞及相关链接；不重复目标定义，无任务可写 "No active task"。]

## Next Check
[可选：所属目标 → 缺口 → 动作与预期证据 → 决策或停止条件。]

## Milestones
- [可选：粗粒度结果、日期、证据链接；合并旧项。]

## Deferred
- [可选：机会与恢复条件；不代表已批准。]
```

## Daily log template

仅在满足写入判据时用用户本地工作日期（非下次会话）建/追加日志；连续工作留在原文件直到产生新结果。新建用 `Write`，追加先读末尾再用 `Edit`/`StrReplace` 或其他专用文件更新工具锚定（更新 `PROGRESS.md` 同理），不覆盖他项；严禁用 `cat >>`、`tee -a`、`printf >>`、`sed -i`、`python` 等 bash/shell 命令直接更新文件。

```markdown
# Work Log — YYYY-MM-DD

## Pilot
[目的/任务；按需给前序链接。]
- Work and evidence: [结果、决定性命令/来源/产物、验证、局限。]
- Conclusion: [预期 vs 实际；对目标的影响及被证伪假设。]
```

小标题须表意、当天唯一，保留被链接锚点（PROGRESS 引用 `worklog/YYYY-MM-DD.md#task`，日志间引用 `YYYY-MM-DD.md#task`，写前确认目标存在）。不抄状态图或逐次工具调用。

## Recovery and growth

1. 完整读 `PROGRESS.md`；不足时顺当前任务链接读日志。
2. 无链接时按任务搜日志并只读匹配章节；不按日期批量加载、不建空日志、不复制旧笔记。
3. 保持地图简短可重读：细节入日志，合并旧 milestone，移除过时链接但保留结论、决定性限制与证据；不建日志索引或二级归档。
4. 可复用命令、偏好、领域知识与跨领域教训分归 `COMMANDS.md`、`CONVENTIONS.md`、`knowledge/<domain>.md`、`MEMORY.md`，只链接不复制；不列 touched files。

## Legacy migration

`HANDOFF.md` 等旧快照只读：可并入 `worklog/` 与 `PROGRESS.md`，不得写入或新建。仅当遇到无 `Current State` 的旧格式 progress 或 `HANDOFF.md` 时，读 `references/legacy-migration.md`。
